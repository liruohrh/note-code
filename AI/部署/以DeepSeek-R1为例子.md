
# DeepSeek-R1 蒸馏模型本地部署指南

## 一、核心前提：个人只能部署蒸馏版

- **DeepSeek-R1 原版**：6710亿参数 MoE 模型，需要多节点 H100/A100 集群，个人无法部署。
- **你能跑的全是蒸馏模型**：官方用 R1 生成的 80 万条思维链数据，微调 Qwen、Llama 等开源小模型，让它们学会 R1 的推理风格。市面上说的 `deepseek-r1:7b/8b/14b/32b` 全是蒸馏版，与原版 R1 是两回事。

## 二、三个基础概念

### 1. 参数量（7B/32B）
模型里权重的数量。7B = 70 亿个数字。参数越大，能力越强，但更吃显存、速度更慢。

### 2. 精度（FP16 / INT8 / INT4）
每个权重占用的字节数：
- **FP16**：2字节（精度最高，显存占用最大）
- **INT8**：1字节
- **INT4**：0.5字节（显存占用最少，但模型会变“糊”，推理质量有一定损失）

**显存估算公式**：参数量 × 精度字节数 ≈ 模型权重显存。例如 7B×2字节 = 14GB，这就是 FP16 原版会爆掉消费级显卡的原因，必须量化。

- **BF16/FP16 都属于高精度层级**，显存需求远大于 INT4/INT8。用它们跑 7B 模型需要约 14GB 显存，主要适用于训练或微调，纯推理个人玩建议直接用 INT4 量化。
    
- **BF16 还是一种“无损”桥接格式**（且是主流选择）。你在笔记中写的 INT4/INT8 是量化格式，无法直接训练。如果需要微调，流程就是：用 BF16 承载主权重和训练 → 训练完再量化回 INT4 部署。在这个流程中，没人用 FP16 做中间格式，因为它范围小、容易溢出，而 BF16 的范围和 FP32 一致，转换时只需截断尾数，几乎是无损的。

### 3. 蒸馏（Distill）
用大模型教小模型。不是简单压缩，而是让小模型模仿大模型的推理过程，从而在特定任务（如数学、编程）上大幅提升。

## 三、模型规模与精度选择

### 实际可行的参数范围

| 参数规模    | 推荐程度    | 说明                |
| ------- | ------- | ----------------- |
| 1B~3B   | ✔️      | 轻量，CPU 也能跑，适合快速验证 |
| 7B~8B   | ✔️✔️✔️  | **个人主力，性价比最高**    |
| 13B~14B | ✔️（有条件） | 需要较好 GPU，上下文受限    |
| 32B     | ⚠️（极限）  | 高端单卡可玩，必须量化       |
| 70B+    | ❌       | 个人基本不用考虑          |


### 推荐精度组合

- **7B/8B**：INT4（首选）或 INT8  
- **13B/14B**：INT4  
- **32B**：必须 INT4  
FP16 只适合极高显存或不在乎速度的情况，消费级显卡不建议。

## 四、按显卡配置推荐

### 1. 无独显/纯 CPU（内存≥16GB）
- **可跑**：1B/3B，或 7B INT4 极慢版  
- **工具**：Ollama（自动适配）、llama.cpp  
- **提醒**：纯 CPU 推理慢是因为矩阵乘法并行度远不如 GPU，能加一张入门独显就会有数量级提升。

### 2. 主流游戏显卡（RTX 3060/4060，8~12GB）
- **最佳选择**：7B/8B INT4 模型  
- **勉强可跑**：14B INT4（需限制上下文长度，否则容易爆显存）  
- **推荐模型**：`deepseek-r1-distill-qwen-7b`、`deepseek-r1-distill-llama-8b`

### 3. 高端单卡（RTX 3090/4090，24GB）
- **7B/8B**：速度飞快，日常使用体验最佳  
- **14B**：轻松运行  
- **32B INT4**：可跑，推理速度约 28 token/s（4090），数学推理能力强（AIME 2024 得分 72.6%）  
- **建议**：日常用 7B，重度推理任务切 32B。

### 4. 多卡发烧（2×3090/4090）
- **32B**：流畅  
- **70B INT4**：勉强可玩，但性价比不高。

## 五、最易忽略的陷阱：上下文长度（KV Cache）

### 原理
模型生成每个字时，需要“记住”之前所有内容，这部分记忆（KV Cache）会单独占用显存，**与模型权重显存是两笔账**。  
- 能加载模型 ≠ 能开长上下文  
- 聊得越久，KV Cache 占用越大，直到显存爆掉。

### 典型额外显存占用

| 模型 | 上下文长度 | 额外显存约 |
|------|-----------|-----------|
| 7B   | 8K        | ~2GB      |
| 32B  | 8K        | ~10GB     |

因此，14B 模型在 12GB 显卡上，权重占 9GB，加上 8K 上下文的 KV Cache 就可能直接溢出。

### 解决办法
如果模型加载正常，但聊几句就崩溃/报显存不足，**降低上下文长度**。例如在 Ollama 中设置 `num_ctx` 参数为 4096 或更低。

## 六、最快上手路径（Ollama）

完全不必先学理论，两条命令搞定：

```bash
# 安装 Ollama
curl -fsSL https://ollama.com/install.sh | sh

# 直接运行 8B 蒸馏版（自动使用 INT4 量化，硬件自动适配）
ollama run deepseek-r1:8b
```

Ollama 会自动选择最优量化版本（默认 Q4_K_M，平衡质量与显存），跑起来就说明选对了，报错再回来调参数。

## 七、重要提醒：纯文本模型，不支持看图

DeepSeek-R1 系列蒸馏模型**只能处理文字**，不能识别图片。如果需要“本地看图+推理”，应选择 MiniCPM-o 等多模态模型；如果目标是本地强文本推理（写代码、逻辑分析），则选 R1 蒸馏版。两者用途不同，不要混淆。

---

**总结**：个人部署 DeepSeek-R1 就是玩蒸馏版，选 7B/8B INT4 是最普适的方案，用 Ollama 一键启动，注意上下文长度别开太高，纯文本任务用它就对了。
